# Welcart 商品画像移行アシスタント（AG FLOLIST 移行用）

対象サイト: https://agflolist.com/  
対象: CSV移行済みの商品49件 / FTPアップロード済み元画像173点（縮小画像は除外）

## 利用手順

1. **必ずWordPressのDBと uploads をバックアップ**。可能ならステージングでテストしてください。
2. 添付ZIPを「プラグイン → 新規プラグインを追加 → アップロード」からインストール、管理者で有効化。
3. 「ツール → Welcart 画像移行」を開きます。
4. 配置確認が173/173点か確認。違う場合は `wp-content/uploads/YYYY/MM/` の階層を確認してください（`uploads/uploads/` の二重階層は誤りです）。
5. 「メディア一括登録を開始」を押します。6枚ずつ処理し、登録済みは重複しません。サーバー負荷が高ければ中断して後から再実行できます。
6. まず1商品で「画像を選ぶ」。メディアからメイン→サブの順で選び、商品編集画面と公開画面で確認します。
7. 問題なければ残りの商品も紐付けます。登録済みの画像があっても保存操作しない限り変更されません。
8. 商品説明内に古いドメインが残っている場合だけ、説明URL置換を実行してください。
9. 移行が終了したらプラグインを無効化・削除します。

## 重要

- 今回の元画像には、商品コードとファイル名が一致しないものが多くあります。したがって **商品画像の完全自動割当ては行いません**。商品説明内の画像はメイン画像の保証がないため、参考サムネイルとして表示しています。
- FTPに置いただけの画像はWordPressメディアに登録されていないため、①の工程が必要です。
- 商品画像登録にはWelcartの正式な `wel_get_item()` と `wel_update_item_data()` を使用しています。保存後に再取得して検証します。
- 適用画像リストの先頭がメイン画像です。保存時にアイキャッチ未設定なら1枚目をWordPressのアイキャッチにも追加します（既存のアイキャッチは上書きしません）。
- アップロード済みの縮小画像（`-150x150.jpg` など）はメディアに重複登録しません。WordPress側で必要なサイズが再生成される場合があります。
- 実際のインストール先サーバーでは未実行・未検証です。最初は**1商品でテスト**してください。
- image プラグインを無効化しても設定済みの画像は残ります。削除する前に必要な画像の表示確認を行ってください。
- 商品説明内の `wp-image-旧ID` というCSSクラスは置換しません。HTMLの画像URLだけ置換します。

## v1.1.0（商品コード照合修正）

- 2026年10月19日、移行先 agflolist.com から再エクスポートされた49商品のCSVで商品コードとPost IDを確認しました（49件一致）。
- 従来の `_itemCode` メタデータに依存した照合を修正。移行先エクスポートのPost IDを起点に、`wel_get_item($post_id, false)['itemCode']` と完全一致した商品だけを操作します。
- **既存の商品CSVを再インポートする必要はありません。**
- プラグイン更新方法：管理画面 → プラグイン → 新規追加 → ZIPアップロード → 既存プラグインを上書き。更新後、ツール → Welcart画像移行から「商品コード照合」の件数を確認します。
- 元画像173点の「メディア一括登録」を行っても、商品との関連付けは自動では行いません。各商品の画像を目視確認して適用してください。

## v1.2.0 （「No Image」が残る症状の診断）

- 「画像の状態を診断」を各商品に追加（読み取り専用）。画像ID・Welcart メイン画像取得・アイキャッチ・添付ファイルの存在を表示。
- 商品画像の保存後、`clean_post_cache()` を実行。画像ID保存だけでなく `wel_get_main_pict_id($post_id, false)` と一致するかを案内。
- **画像が見えない原因は、現時点では未確定**。診断結果で「未保存」「メイン画像取得不一致」「表示問題」のどこに問題があるか切り分けます。
- CSVには `itemPicts` が含まれないため、商品画像の関連付け結果はCSVからは判定できません。
- 商品名・価格・在庫・カテゴリーに触れない。操作前にはDBと uploads のバックアップを取ること。
